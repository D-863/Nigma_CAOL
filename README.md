# Nigma_CAOL
![CAOL_LOGO](caol_icon.png)

## (Currently in developement.)
nCAOL is a C based ***Cross Architecture Operation Layer*** in any space, created to implement ***Operations*** across vast Subjects in various Forms and Layers, yet without paying any unnecessary runtime cost despite the utilized Architecture, OS, CSTDLIB, Compiler and Standard.

It's also free for anyone, as in both speech and beer(Libre and Gratis, use it with freedom and without charge).

## Overview
In a lack of words, the goal with nCAOL is to provide a layer where the implementation of various ***Operations*** across vast Subjects is more computationally ***Omniversal***; Despite what instructions the underlying Architecture may provide.. And as the acronym's tier 'Layer' may convey, this is fully fulfilled upon compilation.

This enables ***Modules*** to implement their Systems without worrying about what fundamental hardware instruction's the Compiler does not fully expose(SIMD, sin, sqrt, etc) and the respective Syntax of each exposed instruction; Or maybe even how to implement Higher-Level operations from various Subjects like Calculus, Linear Algebra, Geometric Algebra and so on..

***But that's certainly not all!***

As a consequence from the concept of ***Omniversality***, nCAOL also implements generic interfaces that handles each specific between realms, and how each realm infuences each other and how all changes across versions; No more platform preprocessor-spaghetti.

**WARNING:** There is potentially a single requirement too ***Manually*** specify within 'enables.h', which is either the utilized OS **or** CSTDLIB; In a nutshell, it's respectively a nonstandard-path and self-included-define kind of problem that is beyond the Compiler's grasp.. **But**, if the respective identification of either the utilized OS or CSTDLIB has already been silently providied to the Compiler, then this paradox is resolved.

Wow, that's a lot of resolved Nightmares! Hopefully..
